# 3주차 과제: 유사한 항목 찾기

원문: https://github.com/codingchild2424/2026-lecture-bigdata-practice/tree/main/w03-lsh

## 무엇을 해야 하나요?

| 과제 | 해야 할 일 | 제출 결과 |
|---|---|---|
| Task 1 | Jaccard, 한 번의 행 순회로 MinHash 서명 생성, LSH 밴드 충돌 구현 | task1_minhash.py |
| Task 2 | 실제 PC에서 문서 수를 늘려 두 방법의 시간·메모리 측정, 교차점과 제곱 증가 확인 | task2_crossover.py, out/crossover.json, out/curve.md |
| Task 3 | 후보만 정확 비교하여 재현율 90% 이상 유지하고 비교 횟수 감소 | task3_scale.py, out/bench.txt |
| 관찰 기록 | 각 과제에서 발견한 사실을 2~3줄로 설명 | out/observation.md |

Jaccard는 두 집합의 교집합 크기를 합집합 크기로 나눈 값입니다. MinHash는 집합을 짧은 서명으로 압축하고, LSH는 서명을 여러 밴드로 나눠 한 밴드라도 같은 문서 쌍만 후보로 선택합니다. 마지막에는 실제 Jaccard 값으로 후보를 확인합니다.

## 이번 구현과 실험 방법

1. Task 1은 각 행의 해시 값을 한 번 계산하여 해당 행을 포함하는 모든 열에 반영합니다. 서명 길이가 밴드 수로 나누어지지 않으면 ValueError를 발생시키고, 남는 값을 버리지 않습니다.
2. Task 3은 고정 시드 246으로 120개 해시를 만들고, 30개 밴드에 4개씩 배치합니다. 역색인으로 각 shingle을 한 번 방문하여 해당 문서들의 서명을 갱신합니다. 후보의 실제 비교는 반드시 제공된 similarity 함수를 사용합니다.
3. Task 2의 원본 `bench.build()[:n]`은 n이 2,120보다 커져도 실제 문서 수가 늘지 않는 문제를 수정했습니다. 동일한 vocabulary 5,000, 집합 크기 60, 시드 246으로 정확히 n개의 독립 문서를 생성합니다. Task 3의 중복 삽입 데이터와 구분되며, bench.py는 수정하지 않았습니다.
4. 시간은 perf_counter, 메모리는 tracemalloc으로 측정합니다. 메모리는 함수 실행 중 Python 할당량의 최대값으로, 입력 문서 생성 비용과 프로세스 전체 RAM은 포함하지 않습니다. 추적 자체의 실행 비용도 시간에 포함됩니다.

## 실행 방법

Python 3.12에서 외부 패키지 없이 실행할 수 있습니다. 터미널에서 w03-lsh 폴더로 이동한 뒤 순서대로 실행합니다. Windows에서는 python3 대신 python 또는 실제 Python 실행 경로를 사용할 수 있습니다.

```text
python task1_minhash.py --verify
python task2_crossover.py --sizes 125,250,500,1000,2000,4000
python task2_crossover.py --sizes 8000
python bench.py --yours
python test_tasks.py
python ../check.py w03
```

측정 스크립트는 기존 crossover.json에 결과를 추가합니다. 다시 실행한 값은 기존 측정값을 덮어쓰지 않으므로 보고서를 갱신할 때 어떤 실행을 사용하는지 명시해야 합니다.

## 제출 방법

### GitHub를 처음 사용할 때: 웹으로 제출하기

1. GitHub에 로그인하고 원본 저장소 https://github.com/codingchild2424/2026-lecture-bigdata-practice 를 엽니다.
2. 우측 상단 **Fork** → **Create a new fork**를 누릅니다. Owner는 본인 계정, 저장소 이름은 기본값을 유지한 뒤 **Create fork**를 누릅니다. Fork는 교수님 저장소의 내용을 본인 계정에 복사하는 기능입니다.
3. 주소가 `https://github.com/본인아이디/2026-lecture-bigdata-practice`인지 확인합니다.
4. 만들어진 본인 저장소의 **최상위 화면**에서 **Add file → Upload files**를 누릅니다.
5. 이번 작업 폴더 옆의 `GitHub_업로드용` 폴더를 엽니다. 그 안의 **w03-lsh 폴더 자체**와 **.gitignore 파일**을 업로드 영역으로 끌어다 놓습니다. `GitHub_업로드용` 폴더 자체나 ZIP 파일을 올리지 마세요.
6. 업로드 목록이 `w03-lsh/task1_minhash.py`, `w03-lsh/out/observation.md` 같은 경로로 보이는지 확인합니다. 기존 교수님 코드 위에 수정한 파일이 반영됩니다.
7. 커밋 메시지에 `Complete week 3 MinHash and LSH assignment`를 적고, 본인 제출 저장소의 main 브랜치에 직접 반영하는 옵션을 선택한 뒤 **Commit changes**를 누릅니다. 화면에 **Propose changes**만 보이면 새 브랜치 및 PR 방식으로 표시된 것이므로 main 반영 여부를 확인해야 합니다.
8. 본인 저장소에서 **w03-lsh → out**을 열어 `crossover.json`, `curve.md`, `bench.txt`, `observation.md`가 있는지 확인합니다. 특히 observation.md를 열어 내용이 보이는지 확인하세요.
9. 수업 제출 페이지에 본인 저장소의 최상위 URL을 제출합니다. 로컬 파일 경로나 교수님 저장소 URL을 제출하면 안 됩니다.

웹 업로드 방법은 [GitHub 공식 안내](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)를 따릅니다. Commit은 변경 파일을 저장소의 기록으로 남기는 단계입니다. 이 과제에서는 교수님 원본 저장소로 Pull Request를 보낼 필요는 없습니다.

### Git 명령으로 제출하기

제출물은 자신의 GitHub 저장소 URL입니다. 제공 저장소를 자신의 계정으로 fork하거나 자신의 저장소에 이 폴더를 올리고, 수정한 코드와 w03-lsh/out 전체를 커밋해야 합니다. 원본 .gitignore는 out을 제외하므로 이번 작업에서는 w03-lsh/out만 예외로 추가했습니다.

```text
git add .gitignore w03-lsh
git commit -m "Complete week 3 MinHash and LSH assignment"
git push
```

현재 폴더는 원본 ZIP에서 내려받은 작업 사본이므로 Git 원격 저장소에 연결되어 있지 않습니다. 본인의 저장소 주소와 계정 연결은 별도로 필요합니다. observation.md는 실제 측정으로 작성한 초안이므로 제출 전에 내용을 이해하고 본인의 표현으로 검토하세요.
