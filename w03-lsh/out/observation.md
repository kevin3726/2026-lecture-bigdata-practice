# 관찰 기록

## Task 1
행마다 해시를 한 번 계산해 해당 행을 포함하는 모든 열에 반영하면 열별 재순회와 반복 해시 계산을 피할 수 있다. 현재 함수는 입력 집합과 서명을 메모리에 보관하므로 디스크 스트리밍 자체를 구현한 것은 아니다.
서명 길이가 밴드 수로 나누어지지 않으면 ValueError를 발생시킨다. S1–S4의 두 해시 추정 1.0과 실제 2/3의 차이를 줄이려면 해시 수를 늘려 표본 오차를 줄일 수 있지만 계산량과 서명 메모리가 늘고, 오차가 반드시 줄어드는 것은 아니다.

## Task 2
Ryzen 7 260·RAM 31.28 GiB·Windows 11에서 관측 교차 구간은 500~1,000개이고 LSH가 처음 이긴 측정 크기는 1,000개다. Chrome·Codex/ChatGPT·Slack이 실행 중이었다.
전수 비교 횟수는 n(n−1)/2로 정확히 제곱 증가하며, 125~2,000의 시간 배율은 3.70~4.38배였지만 2,000→4,000은 5.37배여서 시간 곡선은 완벽히 4배가 아니었다. 배경 부하 등을 통제하지 않았으므로 원인을 특정하지 않는다.
4,000개에서 59.23초, 8,000개에서 250.66초로 1분 대기 기준을 넘었으며 시간부터 불편해졌다. 최대 크기에서 추가 Python 할당 peak는 전수 비교 6,736 bytes, LSH 16,417,396 bytes로 입력 및 전체 RAM을 제외한 값이다.

## Task 3
120개 해시·30개 밴드·밴드당 4행을 선택했다. 경계 근사 (1/30)^(1/4)=0.4273을 임계값 0.6보다 낮춰 재현율을 우선했으며, P(candidate|s=0.6)=1−(1−0.6^4)^30=0.9845이고 무관한 s=0.01에서는 약 3.0×10⁻⁷이다.
실측은 123회 비교로 실제 정답 121쌍을 모두 찾아 재현율·정밀도 100%, 비교 회피율 99.9945%였다. 120해시·12밴드·10행으로 바꾸면 경계 0.7800, P(s=0.6)=0.0702로 올라가며 실측 재현율은 50.4%(61/121)로 떨어졌다.
해싱을 비교 점수에서 제외해도 실제 시간은 발생한다. 이 PC의 작은 입력에서도 해싱 비용 때문에 LSH가 졌고, 문서 수×shingle 수×해시 수가 커지거나 서명·역색인이 RAM을 넘으면 점수만으로 성능을 판단하는 단순화가 부정확해진다.
